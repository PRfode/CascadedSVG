# CascadeSVG: 基于多智能体层叠式架构的 SVG 信息图生成系统

通过调用大语言模型，将用户自然语言需求经多节点级联流水线自动生成为 SVG 信息图。

## 设计理念

将 SVG 生成拆解为 6 个专业化节点，每个节点作为独立的 LLM Agent 负责单一子任务，通过结构化 JSON 进行节点间通信。采用 **"决策 → 执行 → 修正"** 的分层递进模式，将复杂生成任务分解为可控的子步骤。

| 节点 | 角色 | 职责 |
|------|------|------|
| **设计节点** | 思想家 | 理解需求，将用户请求转化为描述文本和主旨标签 |
| **转译节点** | 制图师 | 规划布局，确定层叠结构、配色、基准尺寸 |
| **模板节点** | 工程师 | 识别可复用视觉要素，生成参数化 SVG 模板 |
| **生成节点** | 工人 | 后序递归 + 兄弟协同，生成完整 svg_tree |
| **修正节点** | 质检员 | 边界越界修正 + 7 项质量检查 |
| **渲染器** | 拼装工 | 纯代码将 svg_tree 递归拼装为完整 SVG 文件 |

## 流水线流程

```
用户请求
  → 设计节点 → {description, themes, canvas_hint}
  → 转译节点 → {cascade_structure, color_scheme, ...}
  → [预检#1] → 验证层叠结构合法性
  → 模板节点 → {templates}
  → [预检#2] → 验证模板完整性
  → 生成节点 → 后序递归 + 兄弟节点协同生成 svg_tree
  → [中间 SVG] → 渲染修正前的原始画面（供对比）
  → 修正节点 → 第1轮：边界越界修正 | 第2轮：质量检查
  → 渲染器 → 最终 SVG 文件
```

### 回退路径

| 触发条件 | 回退目标 | 处理方式 |
|----------|----------|----------|
| 预检#1 失败 | 重试转译节点 | 错误信息附加到输入中重新生成 |
| 预检#2 失败 | 重试模板节点 | 错误信息附加到输入中重新生成 |

最多重试 3 次，超过则终止流水线

## 核心设计原则

### 层叠结构（Cascade Structure）

嵌套的 region 树，每个 region 有百分比定位和样式标签。父 region 包含子 region，形成视觉上的容器嵌套关系。转译节点将"横向"的信息流转化为"竖向"的层叠树结构。

### 百分比定位

画布尺寸由转译节点定为整数像素，区域内位置使用小数百分比（0.0~1.0，允许一定溢出），生成节点将百分比转为绝对像素坐标。

### 信息密度约束

生成节点提示词中要求 LLM 自检：高度 ≤ 200px 的区域至少 3 个视觉元素；高度 > 200px 的区域至少 4-5 个元素，垂直覆盖 ≥ 60%。修正节点提供第二道防线。

### 主题色体系

由转译节点生成，包含主色、辅色、背景色、文本色、强调色，传递给所有下游节点。

### 禁画区规则

若某区域有子区域，子区域占据的矩形范围为"禁画区"，父容器不得在其中绘制内容，只能绘制背景、子区域间隙中的连接元素、子区域上方的标题。

### 后序递归 + 兄弟协同生成

生成节点采用后序递归策略：先递归子节点，再批量生成当前节点的所有子节点。同一父节点下的兄弟姐妹区域在单次 LLM 调用中同时生成，确保视觉一致性。

## 节点详述

### 设计节点

- **文件**: `nodes/design_node.py`
- **输入**: 用户自然语言请求
- **输出**: `{description, themes, canvas_hint}`
- **职责**: 理解用户意图，提取核心概念和主旨标签，确定画面比例和风格方向

### 转译节点

- **文件**: `nodes/translation_node.py`
- **输入**: 设计节点输出
- **输出**: `{canvas, base_font_size, grid_unit, color_scheme, cascade_structure, style_descriptions, region_descriptions}`
- **职责**: 确定画布尺寸和基准尺寸，设计主题色，规划层叠结构

### 模板节点

- **文件**: `nodes/template_node.py`
- **输入**: 设计节点 + 转译节点输出
- **输出**: `{templates: [{template_id, params, svg_template}]}`
- **职责**: 分析复用性，仅为使用 2 次以上的 style_tag 生成参数化 SVG 模板（可选的视觉积木）

### 预检脚本

- **文件**: `nodes/precheck.py`
- **预检#1**: 检查层叠结构完整性、画布尺寸、配色完整性、region_id 唯一性
- **预检#2**: 检查模板格式、参数类型、SVG 语法合法性

### 生成节点（核心引擎）

- **文件**: `nodes/generation_node.py`
- **输入**: 设计节点 + 转译节点 + 模板节点输出
- **输出**: `{svg_tree, llm_call_count}`
- **策略**: 后序递归 + 兄弟协同生成，父子节点间传递 content_summary

### 修正节点

- **文件**: `nodes/correction_node.py`
- **第1轮**（条件执行）: 检测并批量修正坐标越界
- **第2轮**（始终执行）: 检查信息密度、排版、对比度、遮盖、父级子级对齐、重复内容、视觉平衡

### 渲染器

- **文件**: `nodes/renderer.py`
- **职责**: 纯代码模块，递归拼装 svg_tree 为完整 SVG 文档
- **特性**: `<layoutText>` 自定义标签自动换行（基于 PIL 计算字符宽度）

## Token 消耗分布

典型的流水线 Token 消耗分布（实际数据因 LLM 和内容而异）：

| 节点 | 占比 | 说明 |
|------|------|------|
| 设计节点 | ~1% | 仅一次 LLM 调用，输出简短 |
| 转译节点 | ~10% | 生成完整布局规划 |
| 模板节点 | ~3.5% | 生成少量模板 |
| 生成节点 | ~67% | 核心环节，多次 LLM 调用 |
| 修正节点 | ~18% | 两轮检查修正 |

## 对照组：单次调用

`compare.py` 实现了对照组——单次 LLM 调用直接生成完整 SVG，用于对比分析层叠式多节点架构的收益与成本。

**核心发现**: 层叠式多节点架构的收益与底层 LLM 的能力呈负相关。模型较弱时架构红利显著（任务分解降低认知负荷）；模型较强时收益递减（信息衰减成为主要制约因素）。

## 项目结构

```
CascadeSVG/
  ├── main.py                 # 入口脚本（解析 --req 参数）
  ├── pipeline.py             # 流水线编排器，串联所有节点
  ├── llm_utils.py            # LLM API 调用封装 + 调用计数 + Token 统计
  ├── logger.py               # 结构化日志 + 计时器 + 文件日志
  ├── example.py              # 测试用例管理器
  ├── compare.py              # 对照组：单次 LLM 调用生成 SVG
  ├── structure.md            # 架构设计文档
  ├── think.md                # 开发笔记与设计思考
  ├── config/
  │   └── api_key.json        # LLM API 配置
  ├── nodes/
  │   ├── __init__.py
  │   ├── design_node.py      # 设计节点
  │   ├── translation_node.py # 转译节点
  │   ├── template_node.py    # 模板节点
  │   ├── precheck.py         # 预检脚本
  │   ├── generation_node.py  # 生成节点（核心）
  │   ├── correction_node.py  # 修正节点
  │   └── renderer.py         # 渲染器
  ├── report/                 # 实验报告
  └── outputs/                # 生成的 SVG 文件
```

## 运行方式

### 环境要求

- Python 3.8+
- 依赖: `openai`, `Pillow`
- Conda 环境（推荐）

### 配置 API

创建 `config/api_key.json`:

```json
{
  "env_var": "YOUR_API_KEY_ENV_VAR",
  "model": "模型名称",
  "api_base": "https://api.example.com/v1"
}
```

设置环境变量:

```bash
export YOUR_API_KEY_ENV_VAR="your-api-key"
```

### 生成 SVG

```bash
# CascadeSVG 层叠式生成
conda run -n nlp2 python main.py --req "大语言模型的基本原理"

# 对照组：单次调用生成
conda run -n nlp2 python compare.py --req "大语言模型的基本原理"
```

### 测试用例

1. **大语言模型的基本原理**
2. **通俗易懂地解释词向量（Word Embedding）的基本概念**
3. **中山大学的发展历程**
4. **绘制 SVG 流程图，展示从一颗咖啡豆到一杯咖啡的完整生产链（种植、采摘、烘焙、研磨、冲煮）**
5. **YouTube has 10 times more videos than TikTok, TikTok has 2 times more than Kuaishou**

## 问题与限制

- 多智能体之间的遮挡关系理解依赖提示词约束，LLM 不一定完全遵守
- 层叠式架构在强模型下的收益递减是当前主要制约因素
